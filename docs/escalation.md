# Escalation

When a run hits a limit, loops, times out or fails internally, it moves to `ESCALATED` and waits up to 24 hours for a human decision.

## The card

Posted in the ticket's thread in `#agentic-dev` and sent by DM to the Jira assignee:

```
⚠️ ABC-123 paused: Same failure repeated: ci:build:OrderServiceTest:discount_rounding
Iterations 2/3 · Premium requests 22/50 · Actions 48/240 min · PR #418
Diagnosis: Rounding mode differs between the AC (half-up) and the legacy test (half-even). The AC may be ambiguous.
[Resume] [Raise budget +50%] [Take over] [Abort]
Auto-aborts in 24h if nobody acts.
```

The diagnosis is generated by Bedrock (prompt `prompts/diagnosis.txt`) from the reason, the last gate findings, the latest commit messages and the acceptance criteria. Input and output are scrubbed. If Bedrock fails, the card says "Diagnosis unavailable."

## Buttons

| Button | Effect |
|---|---|
| **Resume** | Continue from where the run stopped: wait for Copilot again (`CODING`), re-evaluate gates (`GATES`) or send the fixing instruction again (`FIXING`/`HUMAN_FIX`). Loop detection is skipped once. |
| **Raise budget +50%** | Multiplies iteration, premium-request and Actions-minute budgets by 1.5, then resumes as above. |
| **Take over** | Hands the PR to a human: it is marked ready for review and the run waits for the human outcome. |
| **Abort** | Closes the agent PR and ends the run (confirmation dialog). |

Escalations raised before coding started (readiness or issue creation) cannot be resumed; Resume and Raise budget abort with a hint to comment `/agent restart` on the Jira ticket.

## Who can press them

Any one of:

- the Jira assignee (matched by Slack profile email),
- an email listed in `escalationApprovers` in the repo's `.github/agentic.yml`,
- a member of the Slack user group `@agentic-approvers`.

Everyone else gets an ephemeral "You're not allowed to resolve this escalation."

Each escalation has an ID. The first authorised click claims it atomically; later clicks (double clicks, other people, or buttons on an older card) get "Already handled by @user." After a decision the card's buttons are replaced by "✅ <decision> by @user".

## SLA

If nobody acts within 24 hours the run aborts with "Escalation unanswered for 24h" and the owner is notified through the normal abort messages.

## Kill switches

| Scope | Command | Effect |
|---|---|---|
| All repos | `tools/kill-switch.sh off` | New approvals return `DISABLED`; running tickets escalate with "Paused by kill switch (global)" at their next fixing step |
| One repo | `tools/kill-switch.sh off owner/repo` | New tickets for that repo end as `NEEDS_INFO` "Agentic runs are paused"; running ones escalate at their next fixing step |
| Back on | `tools/kill-switch.sh on [owner/repo]` | — |

Set `SLACK_BOT_TOKEN` to have the script announce the change in `#agentic-ops`. Lambdas cache parameters for 30 seconds.

## Runbook: Take over

1. Press **Take over** on the card.
2. `gh pr checkout <PR>` (the branch is `copilot/...`), make the changes, push.
3. Any human push also sets the run's human-override flag, so the orchestrator stops sending instructions to Copilot.
4. Review and merge as usual; Jira moves to Done when the PR merges.
